# Knowledge Garden Publisher

Knowledge Garden Publisher 是一款面向 Windows 的 Markdown 知识花园编辑与发布工具。它以 Quartz v5 博客为内容载体，让你在一个桌面界面里管理多个博客、整理领域、编写公开或私密笔记、维护图片，并在发布前检查变更。

当前版本：`0.1.5`

> 私密笔记只保存在本机，不会进入公开网站。密码、密钥、身份证件等真正敏感的信息，仍不应写入任何曾经公开过或可能被同步的仓库。

## 功能概览

| 功能          | 说明                                                                      |
| ------------- | ------------------------------------------------------------------------- |
| 多博客管理    | 添加已有本地博客，或从 GitHub 下载博客；支持切换、重命名和移除本机记录。  |
| 地址管理      | 分别显示本地文件夹、代码仓库和线上网站地址；线上网站不限于 GitHub Pages。 |
| 领域管理      | 创建、重命名和删除领域；编辑领域描述与标签，两者均可留空。                |
| Markdown 笔记 | 新建、编辑、自动保存和删除笔记；支持搜索、筛选和 WikiLink 补全。          |
| 公开与私密    | 随时切换笔记可见性。本地可预览两类笔记，发布时只处理公开内容。            |
| 图片库        | 每篇笔记拥有独立图片文件夹，可添加、预览、复制链接、覆盖或删除图片。      |
| 四种预览      | 查看当前笔记、全站本地、线上公开站和发布历史。                            |
| 选择性发布    | 先审查变化，再只发布本次勾选的公开文件；私密内容不能被选中。              |
| 安全验证      | 在隔离的 Git 树中验证，通过后才提交并推送，不夹带未选中的本地修改。       |
| 恢复与诊断    | 自动保存与恢复编辑内容；启动时检查依赖、Git、分支和预览端口。             |

## 界面区域

- **顶部博客菜单**：切换博客、添加本地博客、从 GitHub 下载以及管理博客。
- **左侧笔记栏**：按领域、可见性和关键词筛选，也可新建笔记。
- **中间编辑器**：编辑 Markdown、切换可见性、打开图片库或删除笔记。
- **右侧预览区**：包含“当前笔记”“全站本地”“线上公开站”“历史”。
- **底部发布栏**：显示可发布变化数量，并进入发布审查流程。

## 使用前准备

发布器当前支持 Windows，并需要一个符合本项目结构的 Quartz v5 博客：

```text
blog-root/
├─ content/                 # 公开领域和笔记
├─ private/                 # 私密领域和笔记（必须被 Git 忽略）
├─ quartz/
├─ quartz.config.yaml
└─ package.json
```

若要发布到远程仓库，还需要安装 Git，博客位于 `main` 分支并跟踪 `origin/main`，且系统 Git 凭据可以访问远程仓库。发布器沿用系统 Git 的认证方式，不会读取、保存或要求你粘贴 GitHub 密码或 Token。

## 安装与启动

### 使用 Windows 安装包

运行项目构建生成的 NSIS 安装程序，选择安装目录并完成安装。应用按当前 Windows 用户安装，不要求管理员权限。升级时先退出正在运行的发布器，再运行新版安装程序覆盖安装。

### 从源码运行

需要 Node.js 22+、npm 10.9.2+ 和 Git：

```powershell
npm ci
npm --prefix apps/publisher ci
npm --prefix apps/publisher run dev
```

## 第一次连接博客

### 添加已有本地博客

1. 打开顶部博客菜单，选择“添加本地博客”。
2. 选择博客根目录，等待软件检查目录结构与依赖。
3. 确认显示名称；如果依赖缺失，可按界面提示安装。

此操作只把路径记录到本机软件配置中，不会上传、复制或删除原博客。

### 从 GitHub 下载

1. 打开顶部博客菜单，选择“从 GitHub 下载”。
2. 填写 GitHub 仓库地址和本地保存位置。
3. 显示名称可以留空；留空时使用仓库名称。
4. 等待克隆、安装依赖和结构验证完成。

### 配置线上网站地址

打开“管理博客”，在对应博客中选择“编辑网站地址”。可以填写任意有效的 `http://` 或 `https://` 地址，不要求使用 GitHub Pages。

如果未手动填写，软件会尝试读取 `quartz.config.yaml` 的 `configuration.baseUrl`。解析成功后，“线上公开站”会显示该网站。

## 日常工作流

1. 从顶部菜单选择博客。
2. 在左侧打开已有笔记，或点击“新建笔记”。
3. 编辑 Markdown，等待状态显示“已保存”。
4. 用“当前笔记”检查排版；需要浏览完整站点时打开“全站本地”。
5. 根据需要把笔记设为公开或私密。
6. 点击“检查并发布”，核对公开变化。
7. 只勾选确实要上线的文件，然后点击“验证并发布”。
8. 等待验证、推送和线上部署检查完成。

未勾选的修改会继续保留在本机，不会被本次发布带上。

## 笔记功能

### 新建笔记

点击左侧“新建笔记”，填写：

- **标题**：页面显示的标题；
- **文件名**：小写英文字母、数字和连字符，例如 `probability-theory`；
- **描述**：选填，不填写默认为无；
- **标签**：选填，多项用逗号分隔，不填写默认为无；
- **领域**：笔记所属分类；
- **可见性**：公开或私密。

公开笔记位于 `content/<domain>/<slug>.md`，私密笔记位于 `private/<domain>/<slug>.md`。

### 编辑、搜索与 WikiLink

应用会自动保存，并在切换笔记、切换博客、删除或发布前再次确认保存成功。保存失败时会保留编辑内容并停止后续操作。

左侧栏可按领域、公开/私密状态筛选，也可搜索标题、描述、路径和标签。编辑器支持 `[[目标笔记]]` 和 `[[目标笔记|显示文字]]`，并根据现有公开与私密笔记提供补全。

当前公开笔记转为私密时，软件会清理其他公开 Markdown 中指向它的入站 WikiLink，避免公开站构建出现坏链；重新转为公开不会自动恢复此前删除的链接。

### 删除笔记

删除前会显示确认信息。已发布的公开笔记从本机删除后，还需要发布这次删除变化，线上页面才会下线。

## 领域功能

打开“管理领域”可以：

- 使用“显示名称 + 英文路径”创建领域；
- 修改显示名称；
- 编辑描述与标签；
- 查看公开和私密笔记数量；
- 删除没有笔记的空领域。

领域英文路径创建后暂不能在界面中修改。描述和标签均为选填；清空后相应字段会从领域入口页 YAML 中删除，而不是写入占位文字。

## 公开与私密

### 设为私密

笔记会从公开内容区移入本机私密内容区。它仍可在“当前笔记”和“全站本地”中预览，但不会进入新的公开发布。

若它以前已经上线，必须发布这次公开删除变化，线上页面才会下线。历史提交、他人的 clone、搜索引擎或网络缓存仍可能保留旧版本。

### 设为公开

笔记会从私密内容区移回公开内容区。本地预览仍可使用；完成“检查并发布 → 验证并发布”后，它才会出现在公开网站。

### 隐私边界

- `private/` 必须被 `.gitignore` 排除；
- 发布审查中的私密变化会锁定且不能选中；
- 隔离验证会拒绝包含私密笔记或发布器状态文件的发布树；
- 从公开转为私密不等于抹除 Git 历史。

## 图片库

1. 打开笔记，点击编辑器工具栏中的“图片库”。
2. 若图片文件夹不存在，软件会为当前笔记创建空图片库。
3. 点击“添加图片”，选择一张或多张图片并确认；同名文件需要再次确认才会覆盖。
4. 点击缩略图查看完整预览、文件名、像素尺寸和文件大小。
5. 点击“复制 Markdown 链接”，再把链接粘贴到正文需要的位置。
6. 删除图片前需要再次确认；确认后为永久删除。

图片按笔记文件名隔离保存：

```text
公开：content/_assets/<note-slug>/
私密：private/_assets/<note-slug>/
```

支持 PNG、JPG、JPEG、GIF、WebP 和 AVIF；单张最大 25 MiB，每次最多 50 张。图片库不会自动修改 Markdown 正文。

## 四种预览

- **当前笔记**：快速渲染正在编辑的 Markdown；公开和私密笔记都可以查看。
- **全站本地**：在临时合并工作区构建完整 Quartz 站点，同时显示公开和私密内容，但不发布私密文件。
- **线上公开站**：显示当前博客配置的网站，可清理缓存并刷新；未配置时会引导进入“管理博客”。
- **历史**：查看本地 Git 发布记录和可用的线上部署状态。

## 检查并发布

发布分成两个阶段：

1. **检查并发布**：扫描新增、修改、删除和移动的文件。公开变化默认可选，私密变化不可选。
2. **验证并发布**：在隔离的 Git 树中组装精确的选中内容，验证站点，创建提交并推送到 `origin/main`。

推送后软件会继续检查 GitHub Pages 部署结果，区分“正在部署”“成功”和“失败”。验证失败、分支不安全、已有暂存内容、远程分歧或推送失败时会停止，不会强制推送、硬重置或丢弃未选择的修改。

如果本地分支仍叫 `master`，但明确跟踪 `origin/main`，软件可以执行“安全切换到 main 并继续”。若本地已存在 `main`、上游不一致、有暂存内容或 Git 操作正在进行，软件会拒绝自动重命名并说明原因。

## 常见问题

### 显示“预览端口已被占用”，但功能正常

通常是已有的发布器预览进程仍在使用端口，而当前应用可以连接到它。点击提示右上角的叉只隐藏本次提示；下次启动仍会检查。点击“重新检查”可确认端口是否仍被占用。

### 本地能看到，线上看不到

请确认笔记已公开、发布审查中已勾选相关文件、推送已经完成、部署状态成功，并且“线上公开站”配置的是正确地址。

### 设为私密后线上仍存在

可见性切换先改变本地文件。必须发布对应的公开删除变化，等待线上部署完成。CDN、浏览器和搜索引擎缓存可能需要额外时间更新。

### 图片已加入图片库，但正文没有图片

图片库只管理文件。请点击“复制 Markdown 链接”，再手动粘贴到正文。

### 无法删除领域

只有公开与私密笔记数量都为 0 的领域才能删除。请先移动或删除其中的笔记。

### 启动检查提示依赖不一致

使用界面的依赖修复功能，或在博客根目录执行：

```powershell
npm ci
```

## 命令行使用博客

不使用桌面发布器时，也可以直接操作 Quartz：

```powershell
npm ci
npx quartz plugin install
npx quartz build --serve
```

打开 <http://localhost:8080>。发布前运行完整验证：

```powershell
npm run verify:site
```

## 开发、测试与打包

```powershell
npm --prefix apps/publisher run typecheck
npm --prefix apps/publisher run test:run
npm --prefix apps/publisher run build
npm --prefix apps/publisher run test:e2e
npm run verify:site
```

构建 Windows 安装包：

```powershell
npm --prefix apps/publisher run package:win
```

安装包输出到 `apps/publisher/release/`。构建脚本会下载并校验固定版本的 Windows x64 Node.js 运行时，再将它打入安装包。

## 数据与安全

- 恢复信息保存在博客根目录的 `.garden-publisher/`，该目录不应发布。
- 私密内容只放在 `private/`，不要使用 `git add -f` 强制提交。
- 发布前仍建议检查 `git status --short`。
- 重要博客应定期备份。
- 软件不会重写已经共享的 Git 历史，也不会用强制推送掩盖冲突。
