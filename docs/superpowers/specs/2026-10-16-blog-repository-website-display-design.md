# 博客仓库、网站与本地地址显示设计

## 背景

Knowledge Garden Publisher 当前在博客切换器和管理页面中只显示博客名称与本地目录。用户无法直接确认当前博客连接到哪个代码仓库，也无法从软件中查看或打开实际公开网站。

博客的代码仓库与公开网站是两个独立概念：仓库可能位于 GitHub、GitLab、Gitee 或自建 Git 服务，网站可能部署在 GitHub Pages、其他托管平台或自定义域名。因此界面和数据模型不应把两者都称作 GitHub。

## 目标

- 在顶部当前博客、展开后的博客列表和“管理博客”页面同时显示“仓库 / 网站 / 本地”。
- 仓库地址以本地 Git 仓库真实的 `origin` 为准，不保存重复副本。
- 线上网站地址支持从 Quartz 配置自动读取，也支持每个博客手动覆盖。
- 有安全网页地址时可以在系统浏览器打开。
- 地址缺失、无效或读取失败时不阻止本地博客切换、编辑或管理。
- 旧博客注册表无需用户干预即可继续加载。

## 非目标

- 不在本功能中修改 Git `origin`。
- 不自动部署网站或改变当前发布流程。
- 不把任意 SSH Git 地址猜测成网页地址。
- 不支持 `file:`、自定义协议或带用户名密码的网页地址。
- 不把 `localhost`、回环地址、链路本地地址或私有网络地址当作线上网站。

## 信息架构与界面

三个位置统一使用带标签的详细布局：

```text
Knowledge Garden                         当前
仓库    https://github.com/jin07-72/knowledge-garden
网站    https://jin07-72.github.io/knowledge-garden/
本地    C:\Users\11546\Desktop\web
```

显示位置：

1. 顶部当前博客摘要。
2. 展开后的每个博客条目。
3. “管理博客”中的每个博客卡片。

地址过长时可以在可用宽度内省略或换行，但完整值必须继续通过可访问名称、描述或悬停提示提供。仓库、网站和本地标签必须始终可见，避免用户混淆三类地址。

顶部摘要和展开列表中的切换动作与外部链接必须是并列的独立交互控件，不得在按钮中嵌套链接。键盘用户能够分别聚焦“切换博客”“打开仓库”和“打开网站”。

## 仓库地址

主进程在加载博客列表时，对每个可用博客目录执行只读 Git 查询：

```text
git remote get-url origin
```

仓库地址不写入博客注册表。每次重新加载、切换、添加、下载或恢复博客后重新解析，因此用户在软件外修改 `origin` 后能够看到最新结果。

解析规则：

- HTTP 或 HTTPS 远端：显示完整地址；移除仅用于克隆的结尾 `.git` 后作为可点击网页地址。
- GitHub、GitLab、Gitee 的 SCP 风格或 `ssh://` 地址：转换为对应 HTTPS 仓库网页地址。
- 其他无法可靠转换的 SSH 地址：显示原始 `origin`，但不提供点击。
- 缺少 `origin`、Git 命令失败或输出不安全：显示“未配置仓库”。

解析和错误映射不得把 Git 的原始标准输出、标准错误或可能包含的凭据返回给渲染进程。

## 网站地址

每个博客具有一个可选的手动网站地址覆盖值。有效网站地址按以下优先级得到：

1. 博客注册表中的手动覆盖值。
2. 博客根目录 `quartz.config.yaml` 中 `configuration.baseUrl` 的有效公开地址。
3. 没有有效地址时显示“未配置网站”。

`baseUrl` 或手动输入若省略协议，例如 `example.com`，规范化为 `https://example.com/`。保留合法路径，并使用标准 URL 规范化尾部形式。

以下地址不接受为线上网站：

- 非 HTTP(S) 协议。
- 含用户名或密码的 URL。
- `localhost`、`.localhost`、回环地址、链路本地地址。
- IPv4 私有网段和 IPv6 唯一本地/链路本地地址。
- 无法解析为合法主机名的内容。

当前博客的 `quartz.config.yaml` 使用 `localhost:8080`，不会被当作线上网站；用户首次需要在“管理博客”中填写实际公开地址。

## 管理网站地址

“管理博客”中的每张博客卡片增加“编辑网站地址”操作。

- 输入框显示当前手动覆盖值；自动读取的地址作为说明显示，不伪装成已保存的手动值。
- 保存有效地址后立即更新注册表和三个显示位置。
- 清空并保存表示删除手动覆盖，恢复使用 Quartz 自动地址。
- 无效输入保留在表单中并显示明确错误，不覆盖已有有效配置。
- 繁忙期间禁用保存、取消和其他会改变博客注册表的操作，沿用现有管理器并发保护。

## 数据模型与兼容性

持久化的博客记录新增一个可选字段，用于保存规范化后的手动网站覆盖地址。旧版本记录没有该字段时仍由严格 Schema 接受，不需要破坏性迁移，也不改变名称、本地路径、规范路径和时间戳。

运行时返回给渲染进程的博客视图与持久化记录分离。运行时视图包含：

- 仓库显示文本。
- 可选的仓库网页地址。
- 网站地址来源：`manual`、`quartz` 或 `unconfigured`。
- 可选的有效网站网页地址。

动态仓库信息和 Quartz 自动地址不写回注册表，避免缓存过期数据。只有用户明确保存的手动网站覆盖值会持久化。

## 数据流

```text
博客注册表记录 + 本地博客路径
  -> 主进程读取 Git origin
  -> 主进程读取并解析 Quartz baseUrl
  -> 合并可选的网站手动覆盖
  -> 生成只读博客显示视图
  -> IPC 严格校验
  -> 顶部、展开列表、管理页面显示
```

保存网站地址的数据流：

```text
管理页面输入
  -> IPC Schema 校验长度与基本类型
  -> 主进程规范化并验证公开 HTTP(S) URL
  -> 注册表原子持久化手动覆盖
  -> 重新生成博客显示视图
```

## 安全打开链接

渲染进程不得把任意 URL 直接交给 Electron `shell.openExternal`。

点击“仓库”或“网站”时，渲染进程只发送博客 ID 和链接类型。主进程随后：

1. 重新加载对应博客。
2. 重新解析当前 Git `origin` 或有效网站地址。
3. 确认请求的地址仍与当前受信数据一致。
4. 仅对允许的 HTTP(S) 地址调用系统浏览器。

地址在显示后发生变化、博客被移除、路径不可用或验证失败时，返回安全的用户错误，不打开旧地址或任意替代地址。

## 错误处理

- 仓库查询失败：显示“未配置仓库”，博客仍可使用。
- Quartz 文件缺失、格式错误或 `baseUrl` 不公开：若无手动覆盖则显示“未配置网站”。
- 某一个博客的元数据读取失败：不得导致其他博客从列表消失。
- 保存网站覆盖失败：保持表单打开、保留输入并显示错误。
- 打开外部链接失败：显示安全错误，不泄露原始系统或 Git 输出。
- 不可用博客继续沿用现有恢复流程；地址增强不得绕过路径真实性校验。

## 测试

### 仓库解析

- HTTP(S) 仓库地址可显示和打开。
- GitHub、GitLab、Gitee 的 SCP 风格和 `ssh://` 地址转换正确。
- 未知 SSH 地址原样显示且不可点击。
- 缺失、失败或不安全的 `origin` 映射为“未配置仓库”。
- Git 原始错误和凭据不会跨越 IPC。

### 网站地址

- 读取合法的 Quartz 公开 `baseUrl`。
- 手动覆盖优先于 Quartz 自动地址。
- 删除手动覆盖后恢复自动地址。
- 省略协议的公开域名规范化为 HTTPS。
- 拒绝本地主机、私有/本地 IP、凭据、非 HTTP(S) 协议和非法主机。
- 旧版注册表记录能够加载；手动覆盖能够原子保存和恢复。

### 界面和可访问性

- 顶部摘要、展开列表和管理页面均显示“仓库 / 网站 / 本地”。
- 长地址在窄宽度下不破坏布局，并保留完整可访问文本。
- 切换按钮与外部链接互相独立，不产生嵌套交互控件。
- 键盘能够访问切换、仓库链接、网站链接和网站地址编辑表单。
- 缺少仓库或网站配置时，本地博客仍可切换和管理。
- 保存、取消、错误恢复和繁忙状态符合现有管理器行为。

### 安全和回归

- 主进程在每次打开前重新验证目标。
- 渲染进程无法提供任意 URL。
- 博客切换、添加本地博客、从仓库下载、重命名、移除和恢复流程继续通过。
- Publisher 全量测试、类型检查、Prettier 和生产构建通过。
- 重新打包安装程序，并确认打包后的渲染代码包含新界面。

## 验收标准

- 用户可以在三个指定位置区分仓库、线上网站和本地目录。
- 当前博客能够显示通用仓库信息，不把产品文案限定为 GitHub。
- 用户能够设置 `https://jin07-72.github.io/knowledge-garden/` 并从软件打开。
- 地址缺失或读取失败不会阻断本地写作。
- 所有外部打开动作由主进程根据当前受信状态重新验证。
- 旧博客注册表和现有发布流程保持兼容。
