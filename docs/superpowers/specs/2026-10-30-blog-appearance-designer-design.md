# 博客外观设计器设计

## 目标

在 Knowledge Garden Publisher 中增加“外观设置”，让用户无需手工修改 YAML、SCSS 或主题文件，即可调整博客背景、配色、字体、正文宽度、侧栏和自定义 CSS。用户在本地实时预览修改，确认后通过“一键应用”安全写入博客；线上更新仍由现有“检查并发布”流程完成。

第一阶段完整支持 Quartz。底层同时建立框架适配器边界，为后续 Hugo、Hexo 的导入、预览、发布和外观适配保留扩展入口。第一阶段不得声称已经能够修改 Hugo 或 Hexo 博客。

## 已确认的产品决策

- 功能范围采用完整排版设计器，而非只修改背景。
- 提供预设主题、可调控件和高级自定义 CSS。
- 所有控件先作用于实时预览，点击“一键应用”后才写入文件。
- 应用前自动备份，支持“撤销上次应用”和“恢复默认”。
- 一键应用只更新本地博客与本地预览，不自动发布线上站点。
- 外观修改不得改变 Markdown、公开或私密状态、图片库和发布设置。
- 第一阶段实现 Quartz；Hugo、Hexo 通过后续独立适配器逐步支持。

## 开源案例与复用结论

### Publii

- 仓库：https://github.com/GetPublii/Publii
- 许可证：GPL-3.0。
- 匹配点：本地桌面静态博客管理、主题选项、本地预览和一键上传。
- 局限：自身主题体系，与 Quartz、Hugo、Hexo 不兼容；GPL 代码不得复制进当前 MIT 项目。
- 结论：只借鉴“设置面板 + 实时预览 + 明确发布”的交互，不复制代码。

### TinaCMS

- 仓库：https://github.com/tinacms/tinacms
- 许可证：Apache-2.0。
- 匹配点：React/TypeScript、可视化编辑、预览态与提交态分离。
- 局限：集成体量大，主要面向已接入 Tina 数据层的站点，不能直接统一修改任意静态博客主题。
- 结论：借鉴草稿状态、预览桥接和显式提交边界，不整体引入 TinaCMS。

### Decap CMS

- 仓库：https://github.com/decaporg/decap-cms
- 许可证：MIT。
- 匹配点：React、Git 工作流、配置驱动的静态站点编辑。
- 局限：主要编辑内容而非主题外观，运行形态是站点内管理界面，不是本地 Electron 外观工具。
- 结论：借鉴声明式字段和可发布变化分类，不引入完整 CMS。

### 推荐复用

不嵌入完整 CMS 或页面搭建器。Publisher 保留现有 Electron、React、IPC、预览和发布架构，新增小型外观领域模块。颜色选择器可采用 MIT 许可、React 兼容且无依赖的 `react-colorful`；背景文件继续复用 Publisher 已有的 Electron 原生文件选择与安全路径校验模式。

## 用户界面

### 入口

在 Publisher 顶部操作区增加“外观”按钮。按钮针对当前博客工作；切换博客后重新读取对应博客的外观状态。博客切换、发布准备或其他排他事务进行时禁用入口。

### 面板布局

外观设置使用大尺寸模态界面：

- 左侧是设置面板。
- 右侧嵌入当前博客的本地实时预览。
- 底部左侧提供“恢复默认”和“撤销上次应用”。
- 底部右侧提供“取消”和“一键应用”。

设置面板按以下区域组织：

1. 快速主题：知识花园、纸张、极简等可扩展预设。
2. 背景：纯色、渐变或图片；背景位置、尺寸、固定方式和遮罩强度。
3. 颜色：页面背景、正文、标题、强调色、辅助色、边框与代码块颜色。
4. 字体：标题、正文、代码字体以及基础字号和行高。
5. 排版：正文宽度、左右侧栏显示、侧栏宽度、页面最大宽度和内容间距。
6. 高级：托管范围内的自定义 CSS。

第一阶段不提供任意 DOM 拖拽、模板结构重排或 JavaScript 注入。

## 架构

### AppearanceAdapter

新增框架无关的 `AppearanceAdapter` 接口，职责包括：

- 识别工作区框架与适配能力。
- 读取并规范化当前外观设置。
- 将规范化设置渲染为临时预览 CSS。
- 规划需要创建、修改或删除的托管文件。
- 验证目标文件没有发生外部变化。
- 应用计划、恢复备份和读取历史。

界面只依赖规范化外观模型，不读取 Quartz、Hugo 或 Hexo 的具体文件格式。

### QuartzAppearanceAdapter

第一阶段的 Quartz 适配器负责：

- 读取 `quartz.config.yaml` 中的主题颜色和字体。
- 读取 Publisher 托管的外观清单与样式文件。
- 在 `quartz/styles/custom.scss` 中维护唯一、带明确标记的托管样式引用。
- 把生成样式写入独立的 Publisher 托管 SCSS 文件。
- 把背景图片复制到 Quartz 的静态资源目录下的 Publisher 专用子目录。
- 保留用户原有 `custom.scss` 规则，不重排、不格式化、不覆盖非托管内容。

托管引用必须幂等：重复应用不能产生第二条引用。若现有文件包含冲突、重复标记或无法安全解析的托管区域，适配器停止写入并要求用户修复或恢复，而不是猜测。

### 后续框架适配

Hugo 与 Hexo 分别作为独立子项目实现。适配器必须先完成框架检测、内容目录、静态资源目录、预览命令和发布命令支持，再启用外观编辑。主题没有稳定扩展点时，只提供明确标注的有限设置，不能直接覆盖未知主题文件。

## 数据流

### 打开外观设置

1. Renderer 通过受信任 IPC 请求当前博客的外观快照。
2. 主进程确认请求来自受信任 Publisher 窗口，并选择匹配的框架适配器。
3. 适配器读取外观设置、托管文件指纹、撤销能力和框架支持状态。
4. Renderer 建立只存在于内存中的草稿，不立即写磁盘。

### 实时预览

1. 控件变化更新规范化草稿。
2. Renderer 对输入做即时格式校验。
3. 主进程或纯函数将草稿转换为受限 CSS 文本。
4. CSS 只注入当前本机回环地址的博客预览 frame。
5. 新草稿替换旧临时样式；关闭面板或切换博客时清理注入内容。

预览桥接复用当前预览 frame 的来源、frame 身份和回环地址限制，不放宽 iframe、安全策略或线上站访问范围。

### 一键应用

1. Renderer 提交规范化草稿与打开面板时获得的基线指纹。
2. 主进程重新解析和校验请求，不信任 Renderer 生成的路径或 CSS 文件位置。
3. 适配器重新读取目标文件并验证基线指纹，拒绝覆盖外部修改。
4. 适配器生成跨文件事务计划，包括托管清单、SCSS、引用和背景资源。
5. 事务层先写入备份与恢复日志，再通过临时文件和原子替换提交全部变化。
6. Publisher 重新构建本地预览。
7. 构建成功后记录外观历史并更新界面快照；构建失败则自动回滚全部文件并恢复旧预览。

应用成功后，外观文件作为本地 Git 变化出现。用户仍需进入“检查并发布”选择“外观修改”后才会上线。

### 撤销与恢复默认

- “撤销上次应用”恢复最近一次成功应用之前的完整文件集合，并使用同样的事务与构建验证。
- “恢复默认”只修改当前草稿，先显示预览；用户仍需点击“一键应用”。
- 历史按博客隔离，不能在博客切换后误用另一个工作区的备份。
- 第一阶段只承诺撤销最近一次外观应用，不实现无限历史浏览。

## 文件与发布分类

外观模块只允许访问适配器声明的路径。Quartz 第一阶段允许访问：

- `quartz.config.yaml` 中适配器明确管理的主题字段。
- `quartz/styles/custom.scss` 中唯一的 Publisher 引用标记。
- Publisher 专用托管样式文件。
- Quartz 静态资源目录中的 Publisher 专用背景子目录。
- 工作区内的 Publisher 外观状态、事务日志与备份目录。

发布变化扫描增加“外观修改”分类。它与笔记、图片和领域修改分开显示；不能因为应用外观而自动勾选无关高级配置，也不能自动执行发布。

## 安全与输入约束

- 所有 IPC 请求使用 Zod schema 校验并限制字符串、数组和 CSS 文本长度。
- 路径由主进程适配器生成，Renderer 不得传入任意目标路径。
- 所有真实路径必须位于当前博客根目录，拒绝符号链接、目录穿越和工作区外路径。
- 背景文件限制为已支持的安全图片格式，并限制单文件体积；导入时生成受控文件名。
- 自定义 CSS 不能包含 JavaScript，也不支持写入任意站点文件。
- 自定义 CSS 可以影响博客预览与博客页面，但不能作用于 Publisher 自身界面。
- 不读取或修改线上页面 DOM；实时外观只作用于本地预览。
- 切换博客、退出应用或关闭面板时清理未应用草稿和临时 CSS。

## 异常处理

- 不支持的框架：显示已识别框架与“外观适配器尚未安装”，保持只读，不创建文件。
- 本地预览不可用：允许读取设置，但禁用实时预览和应用，提示先修复预览。
- 外部文件变化：拒绝应用并提示重新加载，不覆盖新内容。
- 托管标记损坏或冲突：拒绝应用并显示具体文件，不自动重写整个 `custom.scss`。
- 背景文件无效、过大或无法解码：导入失败，不改变草稿中已生效的背景。
- 事务写入失败：按恢复日志回滚；如果恢复结果不能确认，显示明确的“不确定”状态并阻止继续应用。
- Quartz 构建失败：回滚刚刚应用的全部外观文件，保留草稿供用户修正。
- 撤销失败：保留当前文件和备份，不删除恢复证据。
- 发布失败：不回滚已确认的本地外观；沿用现有发布失败提示与重试流程。

## 测试

### 单元测试

- 规范化外观模型、默认值和预设展开。
- 颜色、字号、宽度、背景、字体和自定义 CSS 输入校验。
- Quartz 配置读取与只更新允许字段。
- 托管引用首次插入、重复应用幂等、冲突标记拒绝。
- 背景资源文件名、格式、体积和路径安全。
- 框架检测与不支持框架的只读结果。
- 外观变化发布分类。

### Renderer 测试

- 打开、关闭和切换博客时正确加载与清理草稿。
- 控件、预设、自定义 CSS、恢复默认和按钮禁用状态。
- 实时预览只发送最新草稿，过期响应不能覆盖新状态。
- 一键应用、构建错误、外部冲突、回滚和撤销提示。

### 集成测试

- 多文件应用全部成功或全部回滚。
- 应用过程中发生外部修改时停止提交。
- 背景替换与旧托管资源清理保持事务一致。
- Quartz 构建失败后文件字节级恢复。
- 撤销后重新构建成功，并且笔记内容与可见性不变。
- 切换博客后事务、历史和预览隔离。

### Electron 端到端测试

- 在真实 Publisher 中打开外观设置、选择背景、调整颜色和排版并观察本地预览。
- 取消后磁盘无变化。
- 一键应用后重启应用，设置和预览保持一致。
- 撤销上次应用后恢复原效果。
- 发布检查只显示预期外观文件，不自动发布。

## 明确不在第一阶段范围内

- Hugo、Hexo 的实际预览、发布或外观写入。
- 任意主题模板的 DOM 拖拽或页面搭建器。
- JavaScript 编辑或脚本注入。
- 自动在线发布。
- 无限外观历史、云端主题市场或跨博客同步。
- 修改笔记正文、公开/私密状态、图片库或领域数据。

## 成功标准

第一阶段完成后，用户可以在任意通过 Publisher 验证的 Quartz 博客中打开外观设置，使用预设或控件调整完整外观，通过本地实时预览确认效果，并在一次安全事务中应用或撤销。操作失败时原博客保持可构建状态；应用过程不会修改笔记和可见性，也不会绕过现有发布确认流程。
